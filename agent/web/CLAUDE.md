# Веб-прототип тренера по знакомствам — правила для Claude Code

@AGENTS.md

Отвечай и пиши комментарии **по-русски**. Работай этапами из `ROADMAP.md`. После каждого этапа остановись: коротко скажи, что сделано и как проверить, и жди «дальше».

## Что это

AI-тренер по знакомствам для мужчин 18+ (КПТ-подход, не пикап). Агент лежит уровнем выше (`../src`, `../prompts`, `../evals`) и проверен тестами. `web/` — веб-чат на Next.js + Supabase для владельца, психолога и 3–5 девушек из «женской панели». **Это прототип, а не продукт.** Кризисный ответ — заглушка до психолога. Вход — только по белому списку (переключатель «пускать всех» есть, см. README).

Цель в итоге — мобильное приложение. Поэтому вся логика живёт на сервере (API), интерфейс только показывает данные.

## Главные правила (не нарушать)

1. **Агента не переписывай.** Веб вызывает `respond()`, `updateMemory()`, `prepareScene()`, `applyScene()` и т. п. как есть. Если без правки `../src` не обойтись — минимальная правка, объяснить её и прогнать проверки агента (ниже). Результат должен совпасть с тем, что было до правки.
2. **`../prompts/**` и `../evals/cases/**` не трогать вообще.** Методику и тексты ответов тренера не менять и своих не добавлять — ни в промптах, ни в коде.
3. **Ключ Anthropic и секретный ключ Supabase — только на сервере** (переменные без `NEXT_PUBLIC_`). В браузер и в git не попадают.
4. **Минимум личных данных.** Скриншоты не хранить нигде: ни в базе, ни в Storage, ни в логах. В лог — только первая строка ошибки (`lib/errors.ts → logError`), без текста сообщений и base64.
5. **Проще, а не красивее.** Мобильная ширина — в приоритете. Без лишних библиотек: Next.js, Supabase, Tailwind.
6. Версии пакетов и цены моделей — проверять актуальные, не по памяти. Пакеты ставить точной версией (`--save-exact`), не свежее двух недель без причины.
7. Платные прогоны тестов агента (`npm run eval` без `--dry`) не запускать — их запускает владелец.
8. Миграции SQL для настоящего проекта Supabase — сначала показать владельцу, применяет он сам (SQL Editor).

## Как устроено

```
agent/                 ← корень агента (в git не лежит: репозиторий публичный, в git только agent/web)
  src/ prompts/ evals/ ← агент (не трогать, см. правила)
  web/                 ← этот проект
    app/
      page.tsx, chat.tsx         чат (серверная страница + клиентский компонент)
      api/chat/route.ts          сообщение → respond() → сохранить оба сообщения
      api/feedback/route.ts      👍/👎 → messages.feedback
      api/client-error/route.ts  ошибки из браузера → лог сервера
      login/                     вход по почте (ссылка или 6-значный код)
      auth/confirm/route.ts      ссылка из письма (?code= — стандартное письмо, ?token_hash= — свой шаблон)
      settings/                  выход, «Удалить мои данные»
      error.tsx                  понятная страница ошибки
    lib/
      auth.ts       getViewer/requireViewer/requireAdmin — кто вошёл и есть ли он в белом списке (на каждом запросе)
      chat.ts       разговоры, сообщения, карточка памяти, удаление — через секретный ключ
      errors.ts     ошибка API → текст для пользователя; logError
      supabase/     server.ts (от имени пользователя, cookie), admin.ts (секретный ключ, только сервер)
    proxy.ts        (в Next 16 так называется middleware) — обновляет сессию, не пускает без входа
    supabase/       config.toml, migrations/, templates/ (письмо со ссылкой и кодом)
    tests/e2e/      проверки в браузере и через API (только локальный Supabase)
```

- Импорт агента: алиас `@agent/*` → `../src/*` (`tsconfig.json`), импорты с `.ts` (`allowImportingTsExtensions`). `next.config.ts`: корень Turbopack и трассировки — папка агента; `prompts/**/*.md` явно включены в серверную сборку (`outputFileTracingIncludes`). Проверено: после сборки промпты читаются и из другой папки.
- Агент — только из серверного кода, runtime `nodejs`.
- Данные: пишет только сервер (секретный ключ); браузер через RLS может лишь читать своё и только пока он в белом списке. `user_id` — всегда из `getViewer()`, никогда из запроса.
- Сессия разговора кончилась — пауза дольше `MEMORY.sessionGapHours` (`isSessionOver`) или конец сцены тренажёра. Тогда новый разговор (`conversations`).
- В модель — последние 20 сообщений разговора (`HISTORY` в `lib/chat.ts`), первым — сообщение пользователя.
- Сообщения сохраняются **после** ответа: при ошибке в базе не остаётся вопроса без ответа, текст возвращается в поле ввода.
- `messages.kind`: `coach` | `crisis_stub` | `intro` | `persona` | `feedback` | `exit` — по нему интерфейс выделяет кризисный ответ и реплики девушки в сцене.

## Next.js 16 — не то, что в памяти

Читай `node_modules/next/dist/docs/` перед новым API. Уже наткнулись: `middleware` → `proxy.ts`; в `error.tsx` есть `retry()`; на странице есть служебный элемент Next с `role="alert"` (в тестах ищи свои элементы по `data-*`, не по `role="alert"`).

## Проверки

**Агент** (из `~/Documents/agent`, после любой правки `src/`; результат — как до правки):
```
npx tsc --noEmit
npm run eval -- --dry            # оценки в dry случайные — смотреть, что скрипт отработал
npm run eval:safety -- --dry     # было: 34 из 51, crisis/minor 3 из 4
npm run eval:memory -- --dry     # Проверки кода: 14 из 14
npm run eval:trenazher -- --dry  # было: 14 из 26, красные зоны 4 из 9
```
Убедиться, что `src/`, `prompts/`, `evals/cases/` не изменились.

**Веб** (из `web/`):
```
npm run typecheck && npm run build
```
E2E — на локальном Supabase (`npx supabase start`, нужен Docker) и `.env.local`, указывающем на него (см. README → «Локальная разработка»):
```
DRY_RUN=1 npm start   # в другом окне; агент отвечает заглушками, бесплатно
npm run e2e           # права доступа, вход, «пускать всех», чат
npm run e2e:errors    # нужны node tests/e2e/fake-anthropic.mjs и npm start с ANTHROPIC_BASE_URL=http://localhost:4010
npm run e2e:crisis    # ПЛАТНО, несколько центов: npm start без DRY_RUN
```
Тесты стирают пользователей и отказываются работать не с localhost. Новые этапы — добавлять свои `tests/e2e/*.mjs` по образцу.

Перед коммитом: нет ключей в `.next/static` и в логе сервера, нет base64 картинок в логах и ответах API.
