## Сделано

### Этап 2. Supabase ✅

- Вход по почте: ссылка + 6-значный код (свой шаблон — нужен свой SMTP) или стандартное письмо Supabase (`?code=`, срабатывает только в том же браузере).

### Этап 3. Чат ✅
`/api/chat` → `respond(последние 20, { memory })` → оба сообщения в базу с флагами; кризисный ответ выделен; 👍/👎; «Сейчас» подставляет «Я прямо сейчас »; настройки: выход и «Удалить мои данные»; ошибки API — понятным текстом; `error.tsx` вместо белого экрана; ошибки из браузера → лог сервера (`[client] …`).

### Баг «Что-то пошло не так» после ответа ✅
Причина: в новых Chrome/Brave `scrollIntoView` возвращает Promise, а эффект прокрутки в `app/chat.tsx` был без фигурных скобок — React принимал Promise за функцию очистки и падал («destroy is not a function», в сборке — «i is not a function»). Перевод страницы ни при чём. Исправлено скобками; `tests/e2e/chat.mjs` ловит такие ошибки (страница ошибки после каждого сообщения, `pageerror`; `scrollIntoView` подменён, как в новых браузерах). **Правило: эффекты — всегда `useEffect(() => { … })`, без неявного return.**

## Этап 4. Память и скриншоты

### Память
- **Конец сессии → `updateMemory`.** Лениво, в `/api/chat` **до** ответа: если последний разговор закончился (`isSessionOver(last_message_at)` или сцена закрыта) и `memory_updated = false` — собрать его сообщения в `Turn[]` (`role`, `content`, у сообщений пользователя `crisis`/`minorUser`/`minorTarget` из колонок, `scene: in_scene`), вызвать `updateMemory(card, turns)`, сохранить `card` в `memory` (upsert), `memory_updated = true`, записать `usage` (kind `memory`). Ошибка обновления не должна ломать ответ: залогировать (`logError`) и идти дальше; фатальные (`isFatal`) — показать как ошибку API. Почему до ответа, а не в фоне: так первое сообщение новой сессии уже видит свежую карточку (цена — 2–5 с задержки раз в сессию). Если задержка мешает — `after()` из `next/server`.
- Сейчас `currentConversation()` в `lib/chat.ts` просто начинает новый разговор после паузы — сюда и встроить обновление.
- **Экран «Что я о тебе помню»** (`/memory`, пункт в `components/nav.tsx`): карточка словами — `renderMemory(card)`; под ней — список записей с кнопкой «удалить» у каждой и «Забыть всё» (одно подтверждение → `emptyMemory()`). Записи строить из полей карточки (`where[i]`, `goals[i]`, `fearMap.thoughts/situations/avoids[i]`, `ladder.step`, `ladder.done[i]`, `people[i]`, `agreements[i]`, `attempts[i]`, `city`/`country`, `address`); удаление — серверное действие, которое убирает элемент по полю и индексу и сохраняет карточку. Статистику тренажёра (`trainer`) не показывать, но «Забыть всё» её тоже стирает. `path` остаётся null (онбординг ждёт психолога).
- Тест: подменить время (`update conversations set last_message_at = now() - interval '4 hours'`), отправить сообщение → карточка обновилась, `memory_updated = true`; на `/memory` видна запись; удаление одной записи и «Забыть всё» работают. С `DRY_RUN=1` `updateMemory` возвращает «пробный режим» без изменений — для проверки содержимого нужен один платный прогон.

### Скриншоты
- Кнопка «прикрепить картинку» в чате. Всё в браузере, **до** отправки:
  - перерисовать через `<canvas>` — это убирает метаданные (EXIF, геометка);
  - уменьшить: большая сторона ≤ 1568 px, JPEG ~0,85 — получается ≪ 5 МБ (предел `llm.ts`). **Важно для Vercel:** тело запроса функции ≤ 4,5 МБ — держать base64 ≤ ~3 МБ, иначе ужимать сильнее;
  - **«Обрезать шапку»** — одна кнопка, срезает верхнюю полосу (имя, аватар); высота — ползунок, по умолчанию ~12 %;
  - **«Закрасить»** — пальцем или мышью (Pointer Events) прямоугольники, заливаются сплошным цветом; можно несколько; «отменить последнее».
- На сервер — уже обработанная картинка: `{ text, image: { mediaType: "image/jpeg", data } }` (base64 без `data:`). Сервер проверяет тип и размер, кладёт в `images` последнего сообщения пользователя для `respond()` и **больше нигде**: в базу — `content` = текст + «[скриншот]», в лог — ничего (не логировать тело запроса и ошибки с ним). В истории прошлых сообщений картинок нет — только пометка.
- Тест: загрузить картинку, «закрасить», отправить → ответ; в базе только «[скриншот]»; в логе сервера и в ответе API нет base64 (искать `/9j/` — начало JPEG в base64). Ответ по картинке проверить одним платным прогоном.

## Этап 5. Тренажёр и стоимость

### Тренажёр
- Кнопка «Тренажёр» → серверное действие: закрыть текущую сессию (как в памяти выше), `prepareScene(trainerProfile(card))` → новый разговор с `scene = state`, сообщение `intro` (`kind = 'intro'`, `in_scene = true`) — показать его.
- Пока `conversations.scene` не null — сообщения идут в `respond(history, { scene: state, memory })`, где `history` — **только реплики сцены** (его и её, без `intro`), последней — его реплика (так в `evals/trenazher.ts`). Новое состояние — `reply.scene.state` → в `conversations.scene`. Сообщения: его — `in_scene = true`; ответ — `kind = reply.scene.part` (`persona` / `feedback` / `exit`), `in_scene = true`.
- `state.phase === 'ended'` — она сказала последнюю реплику; разбор придёт на **следующее** его сообщение. Показать подсказку и кнопку, которая отправит любое короткое сообщение (например «Разбор»).
- Конец сцены (`part` = `feedback` или `exit`) → `applyScene(card, state)` → сохранить карточку; `conversations.scene = null`; сессия закончилась — следующее сообщение начинает новый разговор (и `updateMemory` по этой сессии: реплики сцены `sessionForUpdate` выкинет сам).
- Визуально: реплики девушки (`persona`) — другим цветом и с подписью «она (сцена)»; разбор и выход из роли — как тренер; `intro` — как карточка сцены.
- Кризис посреди сцены: `respond()` сам прерывает сцену (`part = 'exit'`, `phase = 'stopped'`); если `kind = crisis_stub` — выделить как обычно.
- Тест: сцена до разбора (платно, несколько реплик) или с `DRY_RUN=1` — проверить хранение и переходы.

### Стоимость
- `lib/prices.ts`: цены за 1 млн токенов (вход, выход, чтение кэша, запись кэша) для моделей из `../src/config.ts` (`claude-sonnet-5-5` — тренер и режиссёр, `claude-haiku-5-5` — проверки, роутер, судья сцены, память). **Проверить на https://www.anthropic.com/pricing (или docs.claude.com → Pricing) и указать в комментарии дату и ссылку.**
- Писать `usage` на каждый ответ (`reply.usage`, kind `reply`), на `updateMemory` (`kind memory`, модель `MEMORY.model`), на `prepareScene` (`directed.usage`, kind `scene`, модель `TRAINER.directorModel`).
- ⚠️ `reply.usage` — **сумма** по всем вызовам ответа (Haiku-проверки + Sonnet-тренер), разбивки по моделям нет. Варианты — решает владелец: (а) считать всё по цене тренера (верхняя оценка, без правки агента); (б) минимальная правка `src/` — отдавать usage по моделям (тогда прогнать проверки агента).
- `/admin/usage` (`requireAdmin()`): стоимость по дням, по пользователю (почта — через `supabaseAdmin().auth.admin.listUsers()`), средняя стоимость одного ответа (только `kind = reply`).

## Этап 6. Деплой

- **Главное препятствие:** в git только `agent/web`, а сборке нужны `../src`, `../prompts` и `../node_modules`. Варианты: (а) деплоить из папки владельца через Vercel CLI (проект с Root Directory = `web`, запуск из `~/Documents/agent`; установка — зависимости и агента, и веба) — **проверить по актуальной документации Vercel**; (б) сделать репозиторий приватным и закоммитить агента. Владелец склоняется к (а).
- Переменные окружения в Vercel: `ANTHROPIC_API_KEY`, `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SECRET_KEY`. Регион функций — рядом с Supabase (Франкфурт). `maxDuration` у `/api/chat` = 120 с.
- Supabase → Authentication → URL Configuration: Site URL и Redirect URLs — адрес Vercel.
- **SMTP** (например Resend, лучше со своим доменом) → тогда можно поставить свой шаблон письма (`supabase/templates/magic_link.html`: ссылка, работающая в любом браузере, + код) и пускать психолога и панель. Поднять лимит писем в Supabase (по умолчанию 30/ч).
- `web/README.md` дописать: что создать в Supabase, какие переменные куда, как добавить почту в белый список (частично уже есть).
- По желанию владельца: **PWA** (manifest + иконки) — «установить на телефон».
- Под будущее мобильное приложение: `getViewer()` принимает и `Authorization: Bearer <токен Supabase>`, не только cookie (≈10 строк).
- Ручной сценарий из ТЗ на проде: вход → сообщение → скриншот с «закрасить» (в базе только «[скриншот]») → сцена до разбора → «Что я помню» после паузы → «удалить всё» → в базе пусто. Плюс: в ответах API и логах нет ключа и base64.
